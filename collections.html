Detailed Breakdown by Collection Type

1. Lists (List) — Ordered Sequence, Allows Duplicates

ArrayList (Use by default)

When to use: You need fast index-based read access (O(1)) and typically add elements to the end of the list.

When to avoid: You perform frequent insertions or deletions in the middle or beginning of large lists (requires shifting elements, O(n)).

LinkedList

When to use: Rarely required in modern Java. Useful only if you have an existing iterator pointing to an element and want constant-time (O(1)) insertions/deletions at that exact node without array resizing.

When to avoid: General use. It has higher memory overhead per node and worse cache locality compared to ArrayList. Use ArrayDeque for stacks and queues instead.

2. Sets (Set) — Unique Elements Only, No Duplicates

HashSet (Use by default)

When to use: You need to enforce uniqueness and want maximum lookup/insertion performance (O(1) average time). Order of elements does not matter.

When to avoid: You need to maintain insertion order or keep elements sorted.

LinkedHashSet

When to use: You need unique elements while preserving the exact insertion order (e.g., removing duplicates from a list while maintaining sequence).

Performance: O(1) average time, slightly higher memory cost than HashSet to maintain the doubly-linked list.

TreeSet

When to use: You need unique elements maintained in natural sorted order or via a custom Comparator. Also ideal for range queries (e.g., finding all values between A and B, subSet(), higher(), lower()).

Performance: O(log n) time for operations due to underlying Red-Black Tree implementation.

3. Maps (Map) — Key-Value Pairs, Unique Keys

HashMap (Use by default)

When to use: You need fast lookup, insertion, and deletion by key (O(1) average time) where key order does not matter.

When to avoid: Multi-threaded scenarios without external synchronization, or when order matters.

LinkedHashMap

When to use: You need to maintain key insertion order or build an LRU (Least Recently Used) cache (using access-order mode via constructor).

TreeMap

When to use: You need keys sorted automatically or require navigational key lookups (e.g., firstKey(), ceilingKey(), floorKey()).

Performance: O(log n) time complexity.

ConcurrentHashMap

When to use: Highly concurrent multi-threaded applications requiring thread safety without locking the entire map (uses bucket-level lock stripping/CAS operations).

4. Queues & Deques (Queue / Deque) — Processing Order

ArrayDeque (Use by default for Queue & Stack)

When to use: Standard FIFO (First-In-First-Out) Queue or LIFO (Last-In-First-Out) Stack operations. Faster and uses less memory than LinkedList or legacy java.util.Stack.

Note: Does not allow null elements.

PriorityQueue

When to use: Elements need to be retrieved in order of priority (min-heap or max-heap) rather than insertion sequence (e.g., task schedulers, Dijkstra's algorithm).

Performance: O(log n) for insertion and removal.
